## 1. 功能与需求

首日实现可复用的模型接入模块：接收技术问题，校验输入和必要配置，构造请求并调用模型，提取有效文本；失败时给出明确类别，不将异常伪装成正常回答。

- 输入：问题文本、模型名称、API 密钥、服务地址，以及默认或指定的输出 token 上限。
- 输出：去除首尾空白后的回答字符串；已知错误抛出明确异常，由 CLI 展示并返回非零退出码。
- 后续联系：CLI 使用独立的模型接口；工具流程将沿用配置与错误处理职责，并扩展消息和响应接口。
- 首日范围：配置、单次模型调用、CLI、必要测试与文档。未实现工具循环、RAG、数据库、多 Agent、MCP 或前端。

## 4. 设计取舍

1. **SDK 与应用分工。** 使用 OpenAI SDK 对接 DeepSeek 兼容接口，服务目标由 base_url 决定。应用选择消息及参数，检查输入和响应并转换错误；SDK 负责 HTTP 请求、响应对象和 SDK 异常；CLI 负责展示与退出码。
2. **配置加载。** `.env` 相对于配置模块定位，override=False 保持进程环境变量优先。错误指出缺少的配置项，不输出配置值。
3. **单次文本请求。** stream=False、关闭思考模式、max_retries=0，使用 30 秒 SDK 网络超时。没有应用层自动重试；网络超时不是整个任务的严格总时限。
4. **响应检查。** 依次检查非空候选列表、finish_reason=stop、非空字符串正文，通过 getattr 处理缺字段和空消息。只返回有效文本，不检查事实正确性。
5. **错误分层。** 输入/配置错误使用 ValueError；模型失败转为 ModelCallError，分类为 auth、timeout、connection、service、invalid_response。子类异常先于父类捕获，提示不直接拼接完整服务端错误正文。
6. **输出契约。** 回答写入 stdout，错误写入 stderr；成功返回 0，输入/配置问题返回 2，已分类模型失败返回 1。
7. **小需求修改。** 将写死的 max_tokens=1024 改成可选参数，保持默认兼容，在加载配置前校验正整数，再传给 SDK。允许位置或关键字传参；CLI 仍使用默认值。

## 7. 学习复盘与理解状态

已梳理请求构造、异常转换和 CLI 输出链路，能够区分回答内容与 API 调用失败，理解“结构有效不等于事实正确”。已完成 token 上限参数化小修改，通过 Mock 的实际调用记录验证透传。

综合复述暴露的概念已梳理，重点结论如下：

- max_tokens 限制生成输出；输入和生成输出共同受模型上下文窗口约束。
- call_args.kwargs 是测试替身的调用记录，不是命令行输出或实际 token 用量。
- 当前代码先校验问题和参数，再加载配置；system 与 user 消息都参与模型生成。
- 校验关注输入条件、响应结构和调用失败，不提供事实正确性或内容安全审核保证。
- 多轮聊天本身不足以构成 Agent；当前缺少提出行动、执行工具、回传结果并继续或终止的循环。

场景确认已通过：输入为 800 token、max_tokens=256 且上下文容量足够时，256 限制新生成的输出，不会自动裁剪输入；生成达到上限时可能被截断，finish_reason 为 length。当前代码将非 stop 结束归为 invalid_response，不把截断文本作为完整答案返回。

首日基础理解检查完成。主要知识点是在实现、讲解和练习后确认，不记为延迟独立复测或已经熟练掌握完整 Agent 开发。
